Java Execution & JVM Internals

Level 0 Foundation + Level 10 Deep

JVM Architecture Explained

🔵 Class Loader Subsystem
Loads .class files into memory. Three loaders: Bootstrap (core JDK classes), Extension (ext/), and Application (your classpath). Follows delegation model — always asks parent first.
🟠 Heap Memory
All objects live here. Divided into Young Gen (Eden + S0 + S1) and Old Gen. Minor GC runs on Young Gen; Full GC covers the whole heap. GC is triggered when Eden fills up.
🔵 Stack Memory
Each thread gets its own stack. Each method call creates a stack frame containing local variables, operand stack, and frame data. Stack frames are pushed/popped as methods are called/returned.
🟣 Metaspace (Java 8+)
Replaced PermGen in Java 8. Stores class metadata (field names, method bytecode, etc). Lives in native memory (not heap). Can grow dynamically — but set -XX:MaxMetaspaceSize in production.
🟢 JIT Compiler
Just-In-Time compiler converts frequently-used bytecode to native machine code at runtime. C1 (client) compiles fast; C2 (server) compiles with optimization. Tiered compilation uses both.
🟡 Garbage Collectors
Serial GC (single thread), Parallel GC (throughput), G1 GC (default Java 9+, balanced), ZGC (ultra-low pause, Java 15+), Shenandoah (RedHat, concurrent). Choose based on your latency/throughput needs.
IMPORTANT RELATIONSHIPS
JDK = JRE + javac + javadoc + jshell + tools
JRE = JVM + Java Standard Libraries (rt.jar / modules)
JVM = Class Loader + Memory Areas + Execution Engine
Bytecode = platform-independent (runs on any OS with JVM)
JIT = converts hot bytecode to native code for speed

Topic Note Template

use this structure for every topic you study
Create one Markdown (.md) file per topic in IntelliJ. Follow this exact 14-section structure. If you cannot fill in all 14 sections, you don't understand the topic well enough yet.

Sample: Inheritance Template

# Inheritance
## 1. What is it?
A mechanism where a child class acquires the properties and methods of a parent class.
## 2. Why does it exist?
To reuse code and establish an IS-A relationship between classes. Without it, you'd duplicate code across classes.
## 3. Syntax
class Animal { void eat() {} }
class Dog extends Animal { void bark() {} }

Design Patterns Overview

each includes Problem → Solution → When to use → When NOT to use
CREATIONAL
Singleton (moved from your Day 23)
One instance only. Thread-safe version uses double-checked locking or enum.
Factory Method
Create objects without specifying exact class. Decouples creation from usage.
Builder
Construct complex objects step by step. Great for objects with many optional fields.
Prototype
Clone existing objects instead of creating new ones from scratch.
STRUCTURAL
Adapter
Make incompatible interfaces work together. Like a plug adaptor.
Decorator
Add behavior to objects dynamically without modifying their class.
Facade
Provide a simple interface to a complex subsystem.
Proxy
Provide a placeholder that controls access to the real object.
BEHAVIORAL
Strategy
Define a family of algorithms; make them interchangeable at runtime.
Observer
Notify multiple objects when one object's state changes.
Template Method
Define skeleton of algorithm in base class; let subclasses fill in steps.
Command
Encapsulate a request as an object — supports undo/redo.
